## 1. Verdict
Hirelane is a good **job board with a demo** of the product.
- **Real:** only Land and Browse.
- **Demo:** the resume parse is a fixture, the "match" is an FNV hash of the slug, and swipe decisions are never saved.
- **Missing entirely:** every step that makes it an agent: account, fill, hand-off, tracker, replies, return hooks and network.
- **At the base:** no users, sessions, resumes, applications or contacts tables, and no RLS policy in any migration.

## 7. Mechanics to borrow
| Mechanic | Decision | Why |
|---|---|---|
| Receipts (Tsenta) | **now** | the data model already has the snapshot, answers and events; it proves *you* sent it |
| Review every change (Tsenta) | **now for answers** (D3); resume diff later | the "nothing unread" promise made visible |
| Paste a URL (Tsenta) | **now, allowlisted** to public GH/Lever/Ashby hosts | anything else would be scraping; unknown hosts feed board discovery (A5) |
| Email reply drafts (Tsenta) | later | plus-address threading first, which needs no inbox scope |
| WhatsApp (Tsenta) | R2; a minimal opt-in 9am picks if the pilot allows | official Cloud API only |
| MCP/CLI (Tsenta) | later (R3 paid API); **never** a submit path | freshers aren't in terminals |
| Insider connections (Jobright, Simplify) | **own contacts only** (X3); never alumni or hiring-manager data | Amendment A bans scraping and enrichment vendors |
| Curated new-grad lists (Simplify) | **now**, as collections and SEO | the Internships mock is approved |
| A–F grades (career-ops) | never as the display; keep the "don't apply below" rule (A8 ≥ 60%) | ✓/✕ with evidence teaches more |
| Autopilot / bot submit | **never** | contradicts USP #1 |

## 8. PRD holes
1. **Zero or low-supply picks state.** Use nearby cities, remote and internships, all labelled, and never pad. Zero-pick days count toward G0. (R1)
2. **Paste-a-URL.** Allowlisted, with canonical dedupe and a demand log. (R1)
3. **Application receipt.** An immutable snapshot of answers, resume version, timestamps and URL; exportable. (R1)
4. **Reply capture in R1.** A plus-alias lite or a one-tap "I got a reply". (R1)
5. **Email consent text.** The plus-alias trade-off, 90-day raw retention, and separate consent if Gmail is ever read. (R1/R2)
6. **Re-engagement cadence.** Channel, frequency cap, quiet hours, "saved role closing", how it interacts with Pause. (R1)
7. **Tailoring.** Say whether PLAN 5.8 binds, and in which release.
8. **Mobile hand-off detail.** Resume file on the phone, OTP walls, "Couldn't" reason codes, whether a refund applies. (R1)
9. **Campus pilot minimum.** A cohort code and a CSV export, before the G4 dashboard. (R1)
10. **Warmth: core or Plus.** **Owner decision.**
11. **Interview prep.** A story bank, or name it as a non-goal.
12. **Non-tech supply for Rahul,** or drop him from R1.
13. **"Applied elsewhere."** PLAN has `POST /api/applications/external`; the PRD has no row for it.
14. **Mock status.** Approve detail #2–#10 or point the PRD at approved mocks; add paywall and empty-state mocks.
15. **Match ring.** C2 contradicts PLAN §4.1 #16. Confirm that Wrapped supersedes PLAN §4.
16. **Pricing source of truth.** PLAN Phase 7 and G1/G2 disagree. Define when a hand-off counts.
17. **Grievance officer.** It blocks B6, which blocks resume upload.

**Date:** 2026-10-17
**Repo:** `/Users/aagarwal/hirelane` (pnpm monorepo; `apps/web` present, Next 15)
**Method:** Read-only static review (Read/Grep/Glob), plus a limited verification pass that ran local toolchain commands. No application code, config or data was changed. No live credentials, no live ATS or job-board requests, no ingest:run, ingest:record, db:reset or db:fresh.

## Scope note

- **Mocks are concepts, not shipped UI.** `docs/mocks/` (17 HTML files) was used only to judge intent and to list mock-vs-built gaps. Findings are based on what is built in `apps/web/`.
- `apps/web/` was audited separately across product, frontend, security and test layers.
- The project claims **no phase as done**. PLAN.md:3 says "Status: approved for build"; only two acceptance boxes are ticked, both in Phase 2 (PLAN.md:695, 700). Code reality is roughly Phases 0 to 3 plus unplanned landing v2/v3 work. Phases 4 to 9 (accounts, resumes, matching, triage, drafting, approval, tracker, inbound email, autopilot, billing, privacy ops, `packages/network`) are absent. "Missing for Phase 4+" is therefore reported as missing, not as late.

## 1. Executive summary

### Strongest aspects

- **Honest data presentation.** Pay is shown only when stated, with a collapsible normalisation trace and FX date (`apps/web/components/job/PayTrace.tsx:9-23`, `SideCard.tsx:14-18`). The board states the pay-stated ratio (`apps/web/app/jobs/page.tsx:159-161`). Job pages show "Last checked", a Closed chip and de-indexed closed jobs (`SideCard.tsx:41-43`, `JobHero.tsx:24-27`, `job/[slug]/page.tsx:29`). A public `/status` page is computed from the ingest run log.
- **Well-built swipe demo.** Keyboard parity, reduced-motion handling, aria-live announcements, a "Needs you" gate and a 4s undo (`apps/web/components/landing-v3/stack/swipe-stack.tsx:361-383, 408-444`).
- **Good security fundamentals where code exists.** Parameterised board SQL with LIKE escaping (`apps/web/lib/queries/jobs.ts:45,62-88`); sanitize-html allowlist for employer HTML (`apps/web/lib/markdown.ts:11-18`); the only `dangerouslySetInnerHTML` is JSON-LD with `<` escaped (`apps/web/app/job/[slug]/page.tsx:48`); SSRF-guarded logo fetcher (`packages/ingest/src/company/logo-fetch.ts:71-169`); timing-safe ops token compare (`apps/web/lib/ops-auth.ts:15-27`); `.env*` gitignored (`.gitignore:3`).
- **Large unit suites.** Engine 675, web 678, db 62, runner 64, agent 38, ingest 276 of 277 passing (about 1,800 tests). `lint:deps` passes (484 modules, 1028 dependencies), `brand-guard`, `no-submit-guard` and `db:verify-schema` pass.
- **e2e breadth.** 139 of 150 Playwright tests passed across desktop and mobile, including axe, 390px overflow and reduced-motion specs.

### Biggest risks

1. **The headline conversion path dead-ends (UX-1, P1).** Every "Start free" CTA on `/` goes to `#start`, which shows a fixture resume parse and ends at a disabled "Create your account" button. No waitlist or capture exists.
2. **The site describes unbuilt features in the present tense (UX-2, P1).** `/how-it-works` claims resumes are "stored encrypted" and that LLM use is consent-gated. No resume table, no upload path and no consumer of `HIRELANE_MASTER_KEY` exist. This is a privacy misrepresentation to job seekers.
3. **Public API rate limiting collapses to one shared bucket by default (SEC-1, P2; QA-1, P2).** With `TRUST_PROXY_HOPS` unset, one client can exhaust the 60/min public-API budget for everyone. The e2e landing slider failure has the same root cause, but the causal link is inferred, not observed.
4. **There is no release gate.** No CI, no Dockerfile, no root build or lint script. `pnpm test`, `pnpm typecheck` and `pnpm e2e` are red on this checkout (two environment/fixture drift, one product-level limiter defect). Three verification scripts only echo "not implemented" and exit 0.
5. **Retention is structurally absent.** Saves are localStorage-only and have no list page (UX-3). No alerts, digest, accounts or return hook exist.

#### UX-3. No return path: saves are device-local and write-only; nothing brings a user back on day 2 or day 7

- **Severity:** P2 (downgraded from P1 by verifier; the "retention structurally zero" framing ignores direct job URLs, sitemaps and the per-job Saved state)
- **Verdict:** CONFIRMED (core defect); impact scoped down
- **Evidence:**

  - `[VERIFIED: apps/web/components/shell/nav.ts:3-8,14-48]` and `[VERIFIED: apps/web/components/landing-v3/header/landing-header.tsx:9-12]` no "Saved" entry in the header, landing header or footer.
  - `[VERIFIED: grep readSaved|SAVED_KEY|toggleSaved in apps/web]` the only consumers are `useSaved.ts` and `tests/shell.test.tsx`. No page lists saved jobs.
  - `[NOT FOUND]` a `/saved` route, saved-jobs page, job alerts, email digest, push, notification, streak or "new since last visit" marker in `apps/web`.

Plan account sync later.

## 9. Beta verdict

### Verdict: **LIMITED BETA**, scoped to the job board

**Scope of the beta:** browse jobs and companies, evaluate a job (pay trace, requirements, source, last checked), and apply on the employer's own site. The swipe-and-fill autopilot, resume parsing, saves-as-account, alerts and pricing are **excluded** from the beta.

### Reasons

1. **The board is the one part that works end to end.** The job pages, pay honesty, provenance labels, `/status` and the public API are built and mostly tested (about 1,800 unit tests; 139 e2e passing).
2. **The advertised product does not exist.** Every CTA on `/` for the core flow ends in a disabled button (UX-1). The site describes encrypted resume storage and consent-gated LLM use that the code cannot back (UX-2). A beta that invites users into that flow would be misleading to them.
3. **The release gate is red and absent.** `pnpm test` (QA-2), `pnpm typecheck` (QA-3) and `pnpm e2e` (QA-1) fail on this checkout; there is no CI; three verification scripts echo and pass.
4. **Security is acceptable for a board-only beta, not for accounts.** The attack surface is small (no auth, PII or write path), but the default rate-limit configuration lets one client deny service to all public-API users (SEC-1, with QA-1), and the ops cookie holds the raw secret (SEC-2).
5. **Retention is zero.** Saves cannot be listed, and no return hook exists (UX-3). A beta can measure only single sessions until `/saved` and an alert capture ship.

### Why not "ship"

Ship would require the honest-CTA fix, the present-tense fix, a green and CI-backed gate, privacy and terms pages, and retention hooks. None are in place.

### Why not "do not beta"

The board is usable and honest about pay and provenance. The defects are fixable in about two to three weeks (Weeks 1 to 2 of the plan), and none is a data-exposure or auth-bypass risk, since no user data exists.

### What moves it up a level

**To ship:**
- UX-1 and FE-9 resolved: no disabled primary CTA; a working waitlist or `/jobs`-first hero.
- UX-2 resolved: every security and capability claim is either true or tagged "coming soon".
- UX-3 resolved: `/saved` exists and is linked from the nav.
- QA-1, QA-2 and QA-3 resolved: `pnpm verify` and `pnpm e2e` green twice in a row from a clean checkout.
- CI in place (QA-5, SEC-7) with `next build` and `pnpm audit --prod`.
- SEC-1 closed: production refuses to boot without `TRUST_PROXY_HOPS`.
- UX-9: `/privacy`, `/terms` and a contact address live.
- UX-6: branded 404 and error pages.
- UX-4: demo output labelled on the card face.

**Conditions for the current limited beta to be opened (before inviting any user):** UX-2 corrected, UX-1 relabelled (no disabled CTA on `/`), `/privacy` and `/terms` live (UX-9), SEC-1 mitigated at the deploy target, and QA-2 and QA-3 cleared so the team can trust a red or green result.

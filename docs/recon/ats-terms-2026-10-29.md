## The pattern that covers most of them: a generic JobPosting connector
Most employer career sites publish schema.org `JobPosting` JSON-LD so that Google for Jobs can index them, and list job URLs in sitemaps referenced from robots.txt. The data is published specifically for machines. One connector can serve Workday, SuccessFactors career sites, many custom portals of Indian IT-services firms (check each), and Keka tenants that emit JSON-LD.

**Conditions for the connector (proposed; the owner signs off):**
1. **Discovery:** start only from `Sitemap:` lines in robots.txt. Never crawl links. Honour every `Disallow`.
2. **Read:** only job pages listed in the sitemap, parsing only the JSON-LD `JobPosting` block. Store the fields we already store for ATS jobs plus the source URL. Never store page HTML.
3. **Politeness:**
   - ≤ 1 request per second per host
   - an honest user agent with a contact URL
   - `If-Modified-Since` / sitemap `lastmod` to skip unchanged jobs
   - back off on 429/5xx
4. **Never:** call undocumented APIs (`/wday/cxs/…`); log in; submit applications; bypass bot checks or CAPTCHAs; fetch hosts not on the allowlist.
5. **Per-host allowlist:** each employer host is added by hand with a dated line (robots checked, JSON-LD present, site terms read).
6. **Removal:** honour an employer's request to stop within 24 h.
7. **Attribution:** every card shows "<company> careers page · read Nh ago" with a link back (already our A2 pattern).

**Zoho Recruit:** a small RSS connector, under the same conditions 3–7.
